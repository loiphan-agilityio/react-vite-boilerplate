# anti-slop (vendored)

Oxlint rules that reject low-evidence TypeScript patterns, by Dillon Mulroy, MIT (`LICENSE`).

- Source: https://github.com/dmmulroy/anti-slop, `src/` (tests left out)
- Commit: `13909c9e07590f5a85d93c62712259fe14a883f7` (2026-10-14)
- Oxlint: `oxlint` and `@oxlint/plugins` pinned to `1.78.0`, the versions upstream tests with
- Local changes: none to the rules. The repository's `oxlint.config.ts` enables every generic rule and
  the Effect group, and ignores `packages/ui/src/components/` (generated by shadcn).

The project upstream is meant to be vendored and then owned: change a rule here when it does not
fit, and record the change in this file. To take an upstream fix, diff `src/` at a newer commit
against this folder, port what applies, update the commit above, and run `pnpm lint` and
`pnpm check`.

Where a rule is turned off for one line, the comment above the `oxlint-disable-next-line` says why
(`apps/web/src/lib/api/client.ts`: a request body is the outbound JSON boundary).
